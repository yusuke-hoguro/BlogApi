# 学習Planの運用方法

このドキュメントは、AIエージェントと一緒に学習Planを作成し、設計書などの成果物を1 Stepずつ完成させるための運用手順です。

## この運用の目的

- 学習を始める前に、ゴールと学習順序を明確にする。
- AIに完成品を作ってもらうだけでなく、自分で説明・判断できる状態を目指す。
- セッションが変わっても、現在地と次の作業を正確に引き継ぐ。
- 学習結果を、設計書などの再利用できる成果物として残す。

## 使用するファイル

### テンプレート

テンプレートは原本として保管し、直接進捗を書き込みません。

- Plan用: `docs/study/templates/learning-plan-template.md`
- 進捗管理用: `docs/study/templates/learning-progress-template.md`

### 学習テーマごとに作成するファイル

1つの成果物に対して、共通の学習IDを持つPlanと進捗ファイルを作成します。

```text
docs/study/plans/<learning-id>-plan.md
docs/study/progress/<learning-id>-progress.md
docs/architecture/<領域>/<成果物名>.md
```

例として、TerraformによるEC2インスタンス設計を学ぶ場合は、次のようにします。

```text
学習ID: terraform-ec2-instance
Plan: docs/study/plans/terraform-ec2-instance-plan.md
進捗: docs/study/progress/terraform-ec2-instance-progress.md
成果物: docs/architecture/terraform/ec2-instance.md
```

## ファイルごとの役割

| ファイル | 役割 | 主な更新タイミング |
| --- | --- | --- |
| 学習Plan | 何を、なぜ、どの順番で学ぶかを定義する | Plan作成時、学習経路を変更するとき |
| 学習進捗 | 現在地、理解の証拠、未解決事項、次の行動を記録する | Step完了時、セッション終了時 |
| 成果物 | 学習結果として確定した設計や判断を残す | 各Stepで内容を理解したあと |

成果物には、学習途中の一時的なメモや進行状態を混在させません。

## 全体の流れ

```text
学習テーマと成果物を決める
        ↓
AIが現在の理解度を診断する
        ↓
テーマ専用の学習Planを作成する
        ↓
学習者がPlanをレビューして確定する
        ↓
テーマ専用の進捗ファイルを初期化する
        ↓
現在のStepを1つだけ学習する
        ↓
理解確認後、成果物と進捗を更新する
        ↓
次のStepへ進む
        ↓
最後に復習・応用を行う
```

## 1. 学習テーマと成果物を決める

最初に、次の項目を決めます。

- 学習テーマ
- 学習ID
- 完成させる成果物
- 学習したい理由
- 特に理解したい内容
- 今回の対象外

学習Planの基本単位は、設計書などの成果物1件です。大きすぎるテーマは、複数の成果物とPlanに分割します。

## 2. AIに理解度診断とPlan作成を依頼する

最初からPlanを確定させず、AIに現在の知識や経験を確認してもらいます。AIは診断結果を基に、既に理解している内容を短くし、未経験の内容を細かく分割します。

最初の依頼では、少なくとも次のファイルをAIに読み込ませます。

- リポジトリの `AGENTS.md`
- 対象領域に対応する `docs/agents/` 配下の資料
- `docs/study/templates/learning-plan-template.md`
- `docs/study/templates/learning-progress-template.md`
- 対象テーマに関係するコード、設定、既存ドキュメント

進捗管理テンプレートも最初に読み込ませることで、あとで何を理解の証拠として記録するかを考慮してPlanを作成できます。

### 依頼例

```text
TerraformによるEC2インスタンス設計を学習したいです。

成果物は
docs/architecture/terraform/ec2-instance.md
です。

以下を読み込んでください。

- AGENTS.md
- 対象領域に対応する docs/agents/ 配下の資料
- docs/study/templates/learning-plan-template.md
- docs/study/templates/learning-progress-template.md
- TerraformやEC2に関係する既存のコード・ドキュメント

学習IDは terraform-ec2-instance とします。

まず私の理解度を確認してください。
その後、診断結果を反映したPlanを
docs/study/plans/terraform-ec2-instance-plan.md
として提案してください。

まだ学習Stepの実行や成果物の作成は始めないでください。
```

## 3. 学習Planをレビューする

AIが提案したPlanについて、次を確認します。

- 学びたい内容が含まれているか。
- Stepの大きさが、1回ずつ取り組める粒度になっているか。
- 既に理解している内容に時間を使いすぎていないか。
- 前提知識から応用へ進む順番になっているか。
- 成果物の完成だけでなく、理解確認が含まれているか。
- 設計理由、代替案、条件変更の影響を説明する機会があるか。
- 最後に復習・応用Stepがあるか。
- 対象と対象外が明確か。

Planをレビューして確定するまでは、Stepの実行や成果物の作成を開始しません。

## 4. 進捗ファイルを初期化する

Planが確定したら、進捗管理テンプレートを基に、テーマ専用の進捗ファイルを作成します。テンプレート自体には記入しません。

### 依頼例

```text
学習Planを確定します。

docs/study/templates/learning-progress-template.md
を基に、次の進捗ファイルを初期化してください。

docs/study/progress/terraform-ec2-instance-progress.md

PlanのStep一覧を進捗一覧へ反映し、現在地をStep 1の未着手にしてください。
まだStep 1は開始しないでください。
```

初期状態の目安は次のとおりです。

- 全体ステータス: `未着手`
- 現在のStep: `Step 1`
- すべてのStepの状態: `未着手`
- 次回最初に行うこと: `Step 1の目的と完了条件を確認する`

## 5. 現在のStepを1つだけ進める

学習を始めるときは、テーマ専用のPlanと進捗ファイルを読み込ませます。

### 依頼例

```text
以下を読み込んで学習を再開してください。

- docs/study/plans/terraform-ec2-instance-plan.md
- docs/study/progress/terraform-ec2-instance-progress.md

現在のStepを確認し、そのStepだけを開始してください。

最初に、今回の目的、学ぶ論点、完了条件を説明してください。
私が考える前に完成回答や完成した成果物を提示しないでください。
```

各Stepは、原則として次の順番で進めます。

1. AIが目的、論点、完了条件を説明する。
2. AIが質問や演習を提示する。
3. 学習者が予想、回答、判断または草案を出す。
4. AIが正しい点、不足、誤解とその理由を説明する。
5. 学習者が回答や草案を修正する。
6. 理解できた内容を成果物へ反映する。
7. 学習者が重要な内容を自分の言葉で説明する。
8. AIと学習者が完了条件を確認する。

AIによる完成例や模範回答が必要な場合は、学習者が明示的に依頼します。

## 6. Step完了後に進捗を更新する

成果物を作成しただけでは、Stepを完了にしません。学習者が内容や判断理由を説明し、Planに記載された完了条件を満たしていることを確認します。

### 依頼例

```text
現在のStepの完了条件を確認してください。

条件を満たしている場合は、進捗ファイルへ次の内容を記録してください。

- 実施した作業
- 成果物への反映
- 理解できたこと
- 自分の言葉で説明できたこと
- 完了を確認した方法
- 完了根拠
- まだ曖昧なこと
- 次回最初に行うこと

私が確認するまでは、次のStepを開始しないでください。
```

完了条件を満たしていない場合は、状態を `進行中` のままにし、同じStep内で補足説明または再演習を行います。

## 7. Stepの途中でセッションを終了する

Stepの途中で終了しても問題ありません。その場合は状態を `進行中` のままにして、次回の再開地点を具体的に記録します。

### 依頼例

```text
今日はここで終了します。

進捗ファイルに、現在までに実施した内容、まだ曖昧なこと、次回最初に行う具体的な作業を記録してください。
現在のStepは完了扱いにしないでください。
```

`次回最初に行うこと` は、ファイル、見出し、質問または作業を特定できる内容にします。

悪い例:

```text
Step 2を続ける
```

良い例:

```text
EC2へ割り当てるIAMロールの責務を自分の言葉で説明し、Step 2の確認質問へ回答する
```

## 8. 別のセッションで再開する

新しいAIセッションでは、Planと進捗ファイルの両方を読み込ませます。必要に応じて、成果物や関連コードも読み込ませます。

### 依頼例

```text
以下を読み込んで、前回の続きから学習を再開してください。

- docs/study/plans/terraform-ec2-instance-plan.md
- docs/study/progress/terraform-ec2-instance-progress.md

現在地、未解決事項、次回最初に行うことを説明してください。
その後、現在のStepだけを進めてください。
```

AIの説明した現在地が進捗ファイルと一致していることを確認してから、学習を再開します。

## 9. Planを途中で変更する

学習中に前提知識の不足や新しい論点が判明した場合は、Planを変更できます。

変更時は次を行います。

1. AIが変更理由と後続Stepへの影響を説明する。
2. 学習者が変更内容を確認する。
3. Planを更新する。
4. 進捗ファイルのPlan変更履歴を更新する。

完了済みの記録は削除しません。再確認が必要になった場合は、その理由を残します。

## 10. 学習全体を完了する

すべての通常Stepが完了したあと、Planの最終Stepとして復習・応用を実施します。

- 資料を見ずに主要な設計判断を説明する。
- 採用案と代替案を比較する。
- 前提条件が変わった場合の設計変更を考える。
- 代表的な障害の原因と切り分け方を説明する。
- AIの確認問題へ回答する。
- 残った理解不足を今後の学習候補へ記録する。

成果物の完成と理解確認の両方を満たしたら、Planと進捗ファイルの全体ステータスを `完了` にします。

## 運用上の重要ルール

- テンプレートは原本として保ち、テーマ専用ファイルへ複製して使用する。
- Plan確定前にStepを開始しない。
- 一度に扱うのは現在の1 Stepだけとする。
- 学習者が考える前に、AIが完成回答を提示しない。
- 成果物を作ったことと、内容を理解したことを分けて確認する。
- Step完了には、具体的な理解の証拠と学習者の確認を必要とする。
- Step完了時またはセッション終了時に、必ず進捗ファイルを更新する。
- 次回の開始地点は、すぐ着手できる具体的な1アクションとして記録する。
- 実装から確認できる事実、一般的な推奨、AIの推測を区別する。
- パスワード、トークン、秘密鍵などの秘密情報を学習ファイルへ記録しない。

## 開始・終了チェックリスト

### 学習開始時

- [ ] Planと進捗ファイルをAIに読み込ませた。
- [ ] AIが説明した現在地と進捗ファイルが一致している。
- [ ] 今回扱うStepを1つに限定した。
- [ ] Stepの目的、論点、完了条件を確認した。

### 学習終了時

- [ ] 実施した作業と理解できたことを分けて記録した。
- [ ] 完了した場合は、完了根拠と学習者の確認を記録した。
- [ ] 曖昧なことと未解決事項を記録した。
- [ ] 成果物へ反映した内容を記録した。
- [ ] 次回最初に行う具体的なアクションを記録した。
